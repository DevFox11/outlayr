# Icons

Every glyph is Lucide, ISC-licensed, from the public registry. There is no paid pack, no private
registry and no token, and nothing here needs a license seat.

## In components

Icons are React components imported one file at a time:

```tsx
import Trash from "lucide-react-native/icons/trash";

<Icon color={colors.danger} icon={Trash} size={19} strokeWidth={1.8} />
```

`Icon` (src/components/icon.tsx) is the only renderer. It takes `icon`, `size`, `color` and
`strokeWidth`, because the weight of a glyph is part of the design and call sites already pass it.
Its `color` accepts a `ColorValue`, which is wider than Lucide's own `string`: react-native-svg
takes any of them, and the Android tint path hands over a processed colour.

The package root is banned by `no-restricted-imports` (vite.config.ts). Metro does not tree-shake,
so `import { Trash } from "lucide-react-native"` ships all ~1900 icons.

Two gaps in the set, both deliberate:

- **No filled weight.** Anywhere the design used a solid glyph, the same line is drawn heavier.
- **No brand marks.** Lucide dropped them, so the "follow on X" row borrows `external-link`.

Names are the kebab-case file names. Aliases are not importable: `trash` exists, `trash-2` does not.
`apps/native/node_modules/lucide-static/icons` is the authority for what exists.

## The category registry

Categories store their icon name in SQLite, so `REGISTRY` in src/components/category-icon.tsx is
keyed by that stored string. Renaming a key orphans every ledger that used it; add aliases instead
of renames. A name this build no longer ships falls back to `ellipsis`.

Each key maps to one Lucide component. `CategoryIcon` keeps its `type: "stroke" | "solid"` API, and
`solid` renders the same glyph at `SOLID_STROKE` (2.4) because Lucide has no filled variant. 19
entries have no exact Lucide equivalent and carry a deliberate approximation (for example `Sushi`
→ `fish`, `Cheese` → `sandwich`, `Yoga` → `person-standing`); they were chosen by looking at the
original artwork, not by name similarity.

To add one: pick a name that exists under `lucide-static/icons`, import it by path, add the entry,
and make sure the picker offers the same key. Never rename an existing entry.

## The native chrome symbols

iOS tab items and toolbar buttons take an asset-catalog symbol, and Android takes a drawable. Both
are forged at prebuild by `react-native-nano-icons` from the SVGs in
`apps/native/assets/{tab,toolbar,menu}-symbols`, which are committed. Those SVGs are generated:

```sh
cd apps/native
node --import tsx scripts/generate-icons.ts              # every set
node --import tsx scripts/generate-icons.ts tab-symbols  # one set
```

`vp run --filter @outlayr/native gen:icons` runs the same script with no argument (all sets).

- `scripts/icon-sets.ts` holds the kebab name, slug, stroke and ink of each entry.
- `scripts/lucide-raster.ts` reads the SVG from `lucide-static`, drops `class`/`width`/`height`,
  bakes the ink into the stroke and stamps the stroke width. It reads the static package on
  purpose: every module of `lucide-react-native` imports the React Native runtime, so importing it
  from a node script fails.
- `scripts/generate-icons.ts` writes `<slug>.svg` and, for the tab set, `<slug>-selected.svg` at
  stroke 2.5. Lucide has no filled variant, so "selected" reads as the same line drawn heavier.

Changing these SVGs changes the OTA fingerprint: an update built from different symbols will not
apply to an older binary.

The `patches/react-native-nano-icons@1.0.1.patch` entry still applies. It replaces each glyph's real
content bounds with a fixed live area inset by `1.25 * width / 24` on every side, so the symbols
share one optical grid instead of each sitting on its own bounds. Lucide's artwork is drawn inside
a 2-unit padding already, so the alignment is worth re-checking on a simulator after a regeneration.

## Licenses

`src/screens/settings/licenses.json` is generated by `scripts/licenses.ts` from what the release
bundle ships. It lists Lucide (ISC). The two `@hugeicons` entries stay because `panelui-native`
still depends on them and they ship inside the binary; the Pro packs are gone.
